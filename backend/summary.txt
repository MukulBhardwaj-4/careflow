===============================================================================
                         CAREFLOW AI - PROJECT SUMMARY
===============================================================================

PROJECT OVERVIEW:
CareFlow AI is a hospital management system built with Node.js, Express, MongoDB,
and Mongoose. It manages doctors, nurses, patients, prescriptions, medication
reminders, and escalations with real-time notifications and AI-powered features.

===============================================================================
                              TECH STACK
===============================================================================

Backend: Node.js (ES Modules), Express 5.2.1
Database: MongoDB with Mongoose 9.11.4
Authentication: JWT (Access Token + Refresh Token)
Password Hashing: bcrypt 6.0.0
Real-time Communication: Socket.IO
Push Notifications: Firebase FCM
Background Jobs: Inngest
AI Integration: Google Gemini API
Validation: Zod

===============================================================================
                         DATABASE MODELS
===============================================================================

1. ADMIN
   - name (String, required)
   - email (String, unique, required)
   - passwordHash (String, hidden)
   - refreshTokenHash (String, hidden)
   - refreshTokenExpiresAt (Date)
   - timestamps

2. DOCTOR
   - name (String, required)
   - email (String, unique, required)
   - passwordHash (String, hidden)
   - dob (Date, required)
   - specialties (Array of Skill ObjectIds)
   - refreshTokenHash (String, hidden)
   - refreshTokenExpiresAt (Date)
   - timestamps

3. NURSE
   - name (String, required)
   - email (String, unique, required)
   - passwordHash (String, hidden)
   - dob (Date, required)
   - experience (enum: no_experience, 2_plus, 5_plus, 10_plus)
   - shift (enum: day, night)
   - available (Boolean, default: true)
   - refreshTokenHash (String, hidden)
   - refreshTokenExpiresAt (Date)
   - timestamps

4. PATIENT
   - name (String, required)
   - email (String, unique, required)
   - passwordHash (String, hidden)
   - dob (Date, required)
   - condition (String, required)
   - severity (enum: low, medium, high, critical)
   - aiSummary (String)
   - doctorId (Doctor reference)
   - nurseId (Nurse reference)
   - passwordChangeRequired (Boolean, default: false)
   - refreshTokenHash (String, hidden)
   - refreshTokenExpiresAt (Date)
   - timestamps

5. SKILL
   - name (String, unique, required)
   - timestamps

6. REGISTRATION_REQUEST
   - name (String, required)
   - email (String, unique, required)
   - passwordHash (String, hidden)
   - dob (Date, required)
   - role (enum: doctor, nurse)
   - specialties (Array of Skill ObjectIds, for doctors)
   - experience (enum, for nurses)
   - shift (enum, for nurses)
   - status (enum: pending, approved, rejected, default: pending)
   - reviewedBy (Admin reference)
   - reviewedAt (Date)
   - rejectionReason (String)
   - timestamps

7. PRESCRIPTION
   - patientId (Patient reference, required)
   - doctorId (Doctor reference, required)
   - prescription (String, required)
   - medications (Array of medications)
     * medicineName (String)
     * dosage (String)
     * reminderTimes (Array of time strings)
   - timestamps

8. MEDICATION_SCHEDULE
   - patientId (Patient reference, required)
   - prescriptionId (Prescription reference, required)
   - medicineName (String, required)
   - dosage (String, required)
   - reminderTimes (Array of strings, required)
   - startDate (Date, required)
   - endDate (Date, required)
   - timezone (String, required)
   - isActive (Boolean, default: true)
   - timestamps

9. MEDICATION_REMINDER
   - patientId (Patient reference, required)
   - medicationScheduleId (MedicationSchedule reference, required)
   - prescriptionId (Prescription reference, required)
   - medicineName (String, required)
   - dosage (String, required)
   - scheduledAt (Date, required)
   - progress (enum: pending, ongoing, done, default: pending)
   - acknowledgedAt (Date)
   - timestamps

10. ESCALATION
    - patientId (Patient reference, required)
    - nurseId (Nurse reference, required)
    - medicationReminderId (MedicationReminder reference, required)
    - medicineName (String, required)
    - dosage (String, required)
    - level (Number, default: 2)
    - status (enum: ongoing, resolved)
    - resolvedAt (Date)
    - timestamps

===============================================================================
                      AI INTEGRATION & VALIDATION
===============================================================================

GEMINI AI INTEGRATION:

1. PATIENT AI SUMMARY GENERATION
   - Triggered when patient is created or admin requests
   - Generates clinical summary based on condition, severity, age
   - Validates response with Zod schema

   Validation Schema:
   {
     "summary": string (50-500 chars, alphanumeric)
   }

   Response Format:
   {
     "summary": "Patient is a 40-year-old with Type 2 Diabetes.
                 Requires close monitoring of blood glucose levels...",
     "patient": {...patient data}
   }

2. NURSE RECOMMENDATION
   - AI recommends best available nurse based on:
     * Patient severity
     * Patient condition
     * Nurse experience
     * Shift preference

   Validation Schema:
   {
     "name": string (required),
     "experience": enum(no_experience, 2_plus, 5_plus, 10_plus),
     "shift": enum(day, night),
     "available": boolean
   }

   Response Format:
   {
     "_id": "nurseId",
     "name": "Recommended Nurse Name",
     "experience": "5_plus",
     "shift": "day"
   }

3. MEDICATION COMPLIANCE ANALYSIS
   - Analyzes patient's medication acknowledgement history
   - Generates compliance report with recommendations

   Validation Schema:
   {
     "complianceRate": number (0-100),
     "analysis": string (20-500 chars)
   }

   Response Format:
   {
     "complianceRate": 85.5,
     "analysis": "Patient shows good compliance with 85% acknowledgement rate.
                  Consider reminder optimization for afternoon doses..."
   }

AI ERROR HANDLING:
- All AI responses validated with Zod
- If validation fails, log error and return default/cached response
- Prevent cascade failures in background jobs
- Alert admin if AI service fails repeatedly

===============================================================================
                      BACKGROUND JOBS (INNGEST)
===============================================================================

1. GENERATE PATIENT SUMMARY
   Event: careflow/patient/summary.request
   Trigger: Admin creates patient, or manual request
   Process:
   - Call Gemini API for summary generation
   - Validate response
   - Save to patient.aiSummary
   - Handle errors gracefully

2. SCHEDULE MEDICATION REMINDER
   Event: careflow/medication/schedule
   Trigger: When medication schedule is created
   Process:
   - Create MedicationReminder document
   - Schedule notification trigger
   - Idempotent - prevent duplicate reminders

3. SEND MEDICATION REMINDER
   Event: careflow/reminder/send
   Trigger: On reminder time
   Process:
   - Fetch reminder details
   - Send FCM notification
   - Emit Socket.IO event
   - Mark as "ongoing"

4. WAIT AND ESCALATE
   Event: careflow/reminder/wait
   Trigger: After reminder sent
   Process:
   - Wait 5 minutes
   - Check if patient acknowledged
   - If not acknowledged:
     * Create Escalation document
     * Notify assigned nurse
     * Notify assigned doctor
     * Emit Socket.IO events

5. ASSIGN NURSE
   Event: careflow/nurse/assign
   Trigger: When patient needs nurse assignment
   Process:
   - Call AI recommendation engine
   - Select best available nurse
   - Assign to patient
   - Notify nurse
   - Emit Socket.IO event

6. AI SUMMARY BACKGROUND
   Event: careflow/ai/summary/background
   Trigger: Scheduled background task
   Process:
   - Generate AI summary
   - Save to database
   - Non-blocking operation

INNGEST FEATURES:
- Automatic retry on failure
- Idempotency to prevent duplicate jobs
- Step-based execution for reliability
- Error logging and monitoring
- Background processing without blocking API

- Refresh token rotation on each refresh

- Route-level authorization middleware
- Resource-level ownership checks

- Never store plaintext passwords

- Constant-time comparison for tokens

INPUT VALIDATION:
- Zod schema validation on all inputs
- Email validation
- Date format validation
- Enum validation for status/role
- Array length validation

ERROR HANDLING:

===============================================================================
                          USAGE EXAMPLES
===============================================================================

1. DOCTOR SIGNUP & LOGIN
   POST /api/v1/auth/signup/doctor
   Body: { name, email, password, dob, specialties }
   Response: { user, accessToken }

   Then use accessToken in Authorization header:
   GET /api/v1/doctor/profile
   Headers: { Authorization: "Bearer <accessToken>" }

2. CREATE PATIENT & ASSIGN DOCTOR
   POST /api/v1/admin/patients
   Body: { name, email, password, dob, condition, severity, doctorId, nurseId }

   Then doctor can view:
   GET /api/v1/doctor/patients

3. CREATE PRESCRIPTION & MEDICATION SCHEDULE
   POST /api/v1/prescriptions
   Body: { patientId, prescription, medications }

   POST /api/v1/prescriptions/:prescriptionId/schedules
   Body: { startDate, endDate, timezone }

   This triggers Inngest job to:
   - Generate reminders
   - Send notifications at scheduled times
   - Handle escalations after 5 minutes if unacknowledged

4. PATIENT ACKNOWLEDGES REMINDER
   POST /api/v1/patient/reminders/:reminderId/acknowledge

   Response: { success, reminder with acknowledgedAt timestamp }
   This prevents escalation from being created

5. NURSE RESOLVES ESCALATION
   POST /api/v1/nurse/escalations/:escalationId/resolve
   Response: { escalation with resolved status }
